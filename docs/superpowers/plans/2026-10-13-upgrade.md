# 2X Ping upgrade plan (from the five audits)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** make the Deadlock server selector correct and honest, make the app robust, light and clearly worded, and restructure the code into focused classes — without breaking anything that works.

**Spec:** the five audits are the specification, each finding with file:line evidence and a proposed fix:
- `docs/superpowers/audits/2026-10-13-robustness.md`
- `docs/superpowers/audits/2026-10-13-deadlock.md`
- `docs/superpowers/audits/2026-10-13-ux.md`
- `docs/superpowers/audits/2026-10-13-performance.md`
- `docs/superpowers/audits/2026-10-13-architecture.md`
plus `docs/superpowers/specs/2026-10-13-simple-main-screen-design.md` for the main screen.

**Owner's direction (2026-10-13):** Deadlock first and best; Overwatch 2 and Dead by Daylight stay available, marked "in development"; the app must use as little internet/CPU as possible and never affect the connection; object-oriented, efficient structure; do everything an upgrade needs.

## Global constraints
- C# 5 only (no `$""`, `?.`, expression-bodied members, `nameof`); .NET Framework 4.8 WinForms; build with `build.ps1` (Windows csc), tests with `tests/run-tests.ps1` (must stay ALL PASS); `src/` stays flat (both scripts compile `src\*.cs`).
- Every user-facing string bilingual via `T()` / `Lang.T()`; Arabic in the app's Hijazi voice («دحين», «تبغى», «وش»), the app speaks as "we"/neutral consistently.
- Never apply firewall rules, run pktmon or require admin in tests; pure logic gets unit tests.
- Nothing is pushed or published by the team.
- If `dist\2XPing.exe` is locked by a running app, rename it to `dist\2XPing-old-<HHmmss>.exe` before building; never kill the user's app.

## Controller rulings
- R1 Update authenticity (robustness C2: signed releases) is NOT in this plan: it needs a signing key the owner must create and store; it's raised with the owner. Other update fixes (atomic replace, re-verify the extracted exe, wait time) are in Task 1.
- R2 Telemetry heartbeat: 120 s (was 60 s); the dev panel's "online now" window follows it.
- R3 Deadlock strict lock (audit I1): relay-only entry POPs are blocked exactly when they give a route to a blocked hosting datacenter within 20 ms of the best picked route; the card states the cost. Keeps Dubai open for a Europe lock from Riyadh (maz's case), closes it for an SE Asia lock.
- R4 Supabase SQL changes go into `tools/supabase-setup.sql` only; the controller applies them in the dashboard afterwards.

## Tasks

### Task 1: Stability and safety
Spec: robustness audit, all Critical/Important items except C2 (R1), and the architecture audit §5 bugs (lost settings changes during a check/reset, tunnel left up on Stop, firewall apply/remove races and FormClosing leftovers, settings.txt races, card reset on Settings save, `monitorGen` visibility). Includes: offline launch crash (Telemetry.Start), settings.txt lock + atomic write + stable InstallId, try/catch in Task.Run bodies so `busy` always resets, `Ui()` before handle creation, child-process timeouts, `EnsureLocation` negative cache, system tools by full System32 path, FormClosing always removes rules, verify netsh results, startup removes a leftover WireGuard `2xping` service, update replace/rollback/re-verify/wait, remote-address validation per entry (octets ≤ 255, skip bad entries), privacy: no usernames/paths in sent stacks, `traffic` events only after filtering, HTTPS for geo where available; Supabase SQL (R4): global per-minute cap, `kind` whitelist, `refresh_stats` survives bad JSON. SECURITY.md accuracy table updated.
Verify: tests for every pure fix (settings concurrency, address validation, stack scrubbing), build, and a written check of each item in the report.

### Task 2: Deadlock data and player numbers
Spec: Deadlock audit I2, I6, I7, I8. Hosting table corrected (jnb → Europe; bom/bom2/maa/maa2/gum relay-only; dfjr known relay-only; fsn/hel/eat/mwh known hosts without relays shown as display-only "can't be locked" rows); telemetry when the SDR config has a POP missing from the table; Russia shown as a separate queue on EU servers (footnote in the region choices, not a tile); IPv6 relays parsed and blocked; player numbers from `/v1/matches/active` (count `region_mode`, last hour) in the app fallback and in the Supabase job (R4), `/v1/info` kept, the hourly SQL dropped.

### Task 3: Deadlock strict, route-aware lock
Spec: Deadlock audit I1, I3, I5 and ruling R3. All-pairs shortest paths over `typical_pings`; tile ping = best route through open POPs ("via Dubai" when that wins); lock blocks entry relays per R3, never all reachable POPs; the card/longer-route warning states the trade-off with numbers.
Verify: tests with the saved SDR config and the owner's measured pings (audit §1.5): Europe lock keeps dxb open, SE Asia lock blocks dxb+dfjr and reports ~197 vs ~106; build.

### Task 4: Deadlock honest detection
